# 写作、审校与风格档案

## 结构模版
内置于 `assets/structures/`，工作区 `templates/structures/` 可新增或同名覆盖。每个模版 front matter 含 name / fit / length / suggested_theme。

| key | 名称 | 适用 |
|---|---|---|
| tech-deep-dive | 技术深度文 | 原理解析、架构、踩坑复盘 |
| product-launch | 产品发布 | 新产品/功能上线 |
| industry-insight | 行业观察 | 赛道分析、趋势判断 |
| tutorial | 教程指南 | 手把手教程、配置指南 |
| weekly-digest | 周报汇总 | 每周精选、资讯合集 |
| case-study | 客户案例 | 项目复盘、客户成功 |
| opinion | 观点随笔 | 个人思考、评论 |

## article.md 文件头
```
---
title: 标题（≤30 字更佳，上限 64）
digest: 摘要（≤120 字；不填自动截取）
author: 作者（不填用 config.author）
theme: tech-blue
scheme: 黛蓝            # 风格主题的配色
cover: cover.jpg        # 相对本文件
source_url: https://…   # 阅读原文
---
```

## 写作规范
- 手机阅读：段落 ≤4 行；每 300-500 字一个小标题或视觉停顿；重点句加粗。
- 不编造数据、引用、客户评价；第一人称的经历若为代写，标出来请作者确认。
- 标题给 5 个候选：数字型 / 悬念型 / 利益型 / 观点型 / 场景型，附推荐理由。

## 审校清单（写完自动执行，结果交给用户）
1. 错别字、病句
2. 事实与数字是否有来源；资料之间有冲突时指出
3. 敏感与违规：政治、医疗功效、极限词（最/第一/国家级）、诱导分享（转发才能…）
4. AI 腔：「随着…的发展」「总而言之」「值得注意的是」、空泛排比
5. 是否符合结构模版与风格档案
6. 标题/摘要长度、外链数量（会变脚注）

## 风格档案
1. 用户把 3-10 篇过往文章放进工作区 `style/samples/`（或给公众号文章链接）。
2. 写 `style/profile.md`：语气与人设、句式节奏、开头/过渡/结尾习惯、高频与禁用表达、加粗与小标题习惯、配图密度、2-3 段代表性片段。
3. 用户确认后，以后写作严格遵循；用户改稿后询问是否把改动沉淀进档案。
